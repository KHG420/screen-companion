# 0.5.1：同屏搭子、横屏观看与默认清晰度修复

验证日期：2026-09-25。范围为用户要求的名称、图标更新、安卓接收端横屏观看及安卓到安卓默认画质模糊问题；未引入生产依赖、修改信令协议或更换应用包名。

## 修复依据与行为

旧版全屏只改变布局，没有请求观看方向。模拟器锁定竖屏时，共享源已为横屏，点击全屏后接收端仍保持竖屏。另通过双指放大后旋转共享源，复现旧缩放继续生效、只能看见画面中间部分的情况。

本次修正：

- 用户进入全屏后，根据真实接收帧的方向选择横屏或竖屏，支持关闭系统自动旋转时观看横屏内容；共享源方向改变时同步适配。退出全屏恢复 Activity 原先的方向设置。
- 全屏暂时收起系统栏，允许边缘滑动唤出；退出后恢复。为显示缺口保留安全区域。
- 保留同一视频渲染器，使用等比适配。画面比例或观看区域改变时复位缩放与偏移，避免沿用旧视口的放大区域。
- 比例状态与渲染器同生命周期，避免重新协商更换 Java VideoTrack 包装对象后，原渲染回调仍更新已失效的旧状态。

## 功能验收

两台 Android 35 ARM64 模拟器使用实际 WebRTC 屏幕采集、编码和解码。测试画面在四角分别标记 TL/TR/BL/BR，以检查完整性。

- 接收端锁定竖屏，接收横屏画面，点击全屏后横屏展示。
- 全屏内双指放大，再将共享源从横屏切为竖屏、再切回横屏：接收端方向随之改变，四角完整可见，缩放与偏移复位。
- 退出全屏后回到原先的竖屏普通通话布局，通话保持，四角仍可见。
- 接收端临时设置为 1080×2400、共享源为 1920×1080：横屏全屏保留左右黑边，四角完整，没有为了铺满而裁切。
- 最终 Release 包安装到两台模拟器，核对安装后的 APK 与交付文件 SHA-256 一致；通过已部署 HTTPS 服务入房，再验证横屏/竖屏全屏显示。
- 安卓应用抽屉实际显示“同屏搭子”和新小狗图标，脸部与耳朵没有在当前启动器遮罩中被截断。

## 安卓到安卓清晰度

复现使用两台模拟器、同一实际 WebRTC 通话和持续移动文字素材。旧默认为 1920×1080 / 30 FPS / 8 Mbps，自动平衡。接收统计出现 270×480 / 14.6 FPS，发送端显示带宽受限；切换清晰优先后，实际接收恢复到 1080×1920 / 13.2 FPS。同一素材截图中的文字清晰度明显改善。这是一次功能复现，不是固定吞吐或帧率的性能基准。

另由采集尺寸算法确认：1920×1080 上限会将 1080×2400 源缩为 864×1920。新增安卓“高清默认”档为 2560×1440 上限、30 FPS、12 Mbps、清晰优先，保留常见长屏原始像素，并在资源受限时允许降帧。保留均衡和帧率优先供主动选择；不强设最低码率，也不关闭拥塞控制。单元测试覆盖横竖长屏、不放大低分辨率源及默认优先策略。电脑默认与媒体逻辑不变。

最终 Release 包的新建通话中，未手动调整画质，1080×2400 源实际接收为 1080×2400；采样窗口为 7.4 FPS / 3.48 Mbps，软件模拟器不能据此承诺 30 FPS。随后切换横屏、双指放大、切回竖屏与退出全屏继续检查四角及通话状态。
