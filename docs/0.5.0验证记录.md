# 0.5.0 通话体验优化验证记录

验证日期：2026-09-25。范围为安卓客户端和电脑网页，仍为双人 WebRTC 直连优先、TURN 备用中转；没有增加生产依赖或修改信令消息类型。

## 本次实现

- 共享画面占据主要空间；未开启的摄像头不占位，开启后可收起预览。电脑聊天改为按需展开的侧栏，安卓使用底部面板。保留原有小狗素材、首页和通话配色。
- 画质、声音与连接统计集中到次级面板，保留分辨率、1–60 整数 FPS、0.5–80 Mbps 和资源不足时的优先策略。
- 麦克风授权不阻塞入房。安卓首次无权限时用 receive-only 音频方向，避免 libwebrtc 提前初始化 AudioRecord；首次开启录音在同一个 PeerConnection 上重新协商。网页麦克风重试复用现有混音输出轨道。音频采集错误保留房间、画面与聊天。
- 麦克风和共享声音独立开关；拒绝录音可继续共享视频。Android 系统音频仍受源应用的捕获许可限制。
- 消息按需追加，查看历史时保留阅读位置并显示未读。安卓将未读计数放入通话状态，切换全屏、画中画后仍保留；草稿使用可保存的 UI 状态。
- 安卓全屏沿用相同的布局层级和渲染器，解决视频放大后仍按旧窗口大小裁剪的问题。增加缩放、平移、双击复位与画中画入口；观看时保持亮屏。网页提供全屏、平台支持时的画中画和唤醒锁。
- 首帧提示使用实际渲染回调；不将静止画面节流直接误报成断线。
- 邀请链接预填服务和房间，不自动入房或开启采集。部署模板补齐同源 `/v1/rooms` 代理，使安卓导入网页邀请后的 API 地址可用；不改变既有 API 路径和数据格式。

## 自动检查

- Web：18 项 Node 单元测试全部通过；`web/app.js` 与 `web/call.js` 语法检查通过。包括麦克风拒绝、设备丢失与重试、通话结束后的迟到采集清理、独立共享声音静音，以及 AudioContext 等待用户激活时不阻塞入房。
- Android：12 项单元测试全部通过，包括 4 项服务地址/邀请解析、3 项播放音频混合、5 项画质与等比尺寸测试。
- Android：最终 Release 构建成功；Debug/Release lint 均无错误。各有 7 条警告，涉及 PiP 自动进入/动画源区域建议、可更新的依赖版本、备份配置和 Kotlin 扩展建议。当前 PiP 由用户主动进入，未开启离开应用时自动进入。
- `git diff --check` 通过。公开改动及 APK 内容扫描未包含私有测试地址、服务器 IP 或密码。

## 真实浏览器回归

复用现有 Chrome，使用真实 WebRTC 编码、传输和解码；测试输入为可控 Canvas 视频和音调，不等同于真实系统录屏或麦克风硬件验证。22 项断言全部通过：

- 双向文字、双方摄像头、屏幕/摄像头轨道分离与摄像头重新开启。
- 接收实际 3840×2160 帧，热切换至 720p/20 FPS/2.5 Mbps 后再切回 4K；这里验证尺寸与连接保持，不声称持续 4K60。
- 麦克风停止事件后保留屏幕、房间和混音轨道；恢复后继续通话。
- 麦克风静音时共享音频继续；共享音频可独立静音、恢复，停止共享后声音移除。
- 共享交接、重启共享、ICE 重连、挂断清理，以及两端拒绝麦克风后仍能连接和聊天。

网页 UI 检查使用与发布页一致的标记结构：实际视频解码、首帧提示消失、麦克风断开提示/重试、聊天滚动及未读、消息节点复用、画质入口和横向溢出均已检查。在 1600 像素测试视口中，收起聊天后主画面可用宽度从 1179 增至 1529 像素。浏览器全屏进入已验证；本轮没有完成浏览器原生画中画交互验收。

## Android 与跨端检查

使用两台本任务创建的 Android 35 ARM64 模拟器进行功能测试：

- 两端均无麦克风权限时连接与聊天；拒绝录音仍可共享屏幕。
- 已入房、正在共享时授予录音权限，房间和画面保留，麦克风状态恢复。
- 普通观看 → 全屏 → 返回普通观看，以及画中画显示 → 返回通话均检查了实际截图；全屏画面完整，不再按原窗口尺寸截断。画中画在系统动画结束后能显示持续的视频内容。
- 检查过未读跨画中画保存、首帧提示清除，测试期间未发现应用致命崩溃。

最终 Release APK 已安装到模拟器，核对安装后的 APK SHA-256 与交付文件一致，并连接已部署的 HTTPS 电脑网页：

- 成功入房，双方数据通道文字消息互达。
- 安卓拒绝录音后共享视频，电脑实际解码出画面；随后在同一房间授予麦克风权限，通话与共享继续。
- 本次跨端路径使用 TURN，界面观察到约 47–52 ms 网络往返；该数字不是屏幕端到端延迟。
- 电脑测试窗口在后台，跨端检查侧重连接、轨道、解码和消息，没有将后台呈现帧率作为性能指标。

已部署网页四个文件与本地 SHA-256 一致；Nginx 新增房间 API 代理后通过配置检查并重载，安卓成功连通验证了实际路由。

## 验证边界

本轮解决操作空间、权限恢复、状态反馈和切换布局等体验问题，不把这些改动等同于已实现新的编码性能增益。已有各画质/帧率结果见 [0.4.4 验证记录](0.4.4验证记录.md)。尚未完成安卓真机上的持续 4K60、发热、耗电、蓝牙设备切换和复杂弱网验收，也没有本轮 Windows/Linux 实机浏览器性能数据。模拟器功能检查不能替代这些硬件指标。
