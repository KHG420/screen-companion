# 测试与验收

本文件区分自动化、模拟器和真机证据；没有执行的项目不标为通过。

## 自动化范围

- Go：房间两人限制、会话身份验证、信令角色限制、消息重放与重试去重、同时共享互斥、挂断事件、空闲过期、事件窗口、创建/加入限流、TURN 凭证生成、长轮询唤醒；使用 `go test -race`。
- 安卓：服务器地址规范化、拒绝 Release HTTP、拒绝 URL 内嵌账号与路径；使用 JUnit。
- 编译：Debug APK；Android Lint 另行记录。

## 双模拟器验收步骤

使用本任务独立 Google Android Emulator 实例，不复用用户原有 MuMu 数据。

1. 启动本地信令服务，两个设备安装同一 APK，填写同一服务地址。
2. 创建房间、复制房间号、第二台加入；观察两端连接状态与调试 RTP 计数。
3. 任一方接受系统录屏授权，对方收到真实画面；检查横竖屏、全屏观看和缩放。
4. 静音/取消静音、停止共享后语音保留、另一方接替共享。
5. 断网/恢复时状态正确，并保持停止本地采集的入口可用。
6. 挂断后两端回到首页，前台服务和 MediaProjection 均停止。
7. 检查明暗主题、1.3 倍字体、权限拒绝与错误恢复。
8. 关闭本任务启动的实例、信令和临时 TURN 进程，检查资源退出。

调试版通过 `ScreenShareStats` 标签记录累计音频包和视频编码/解码帧数，不记录房间凭证或媒体内容。RTP 音频包验证通道可用，不能等价于真实听感与回声测试。

辅助查看 UI：`python3 scripts/android-ui.py --adb /你的/adb emulator-5554 dump`。

## 仍需真机的指标

- 真实硬件编码器是否满足预期清晰度、帧率和端到端延迟。
- 扬声器回声、降噪、蓝牙耳机与来电抢占。
- 30–60 分钟共享下的发热、耗电、厂商后台策略。
- 不同运营商、4G/5G、跨地域连接以及生产 TURN 配置。

模拟器运行时间与编码速度不能替代这些指标。画面延迟需同时记录源端和接收端时钟画面，不能直接采用网络 RTT。

## 0.1.1 系统声音修复验收（2026-09-24）

根因：0.1.0 仅创建麦克风输入，没有 AudioPlaybackCapture 音源。0.1.1 使用屏幕采集已经获批的同一 MediaProjection 创建内部音频 AudioRecord，采集允许的 MEDIA/GAME/UNKNOWN 播放声音，并在 WebRTC 录音回调中以 48 kHz、单声道 PCM16 与麦克风混合。没有新增生产依赖或修改服务端协议。

麦克风静音改在混音之前处理，因此静音不会关闭共享媒体；停止共享、挂断时释放内部录音器。采集排除本应用 UID，避免把对方语音重复发送。源应用禁止采集、受保护媒体和 Android 不允许采集的音频用途仍保持限制。

验证环境：两台 Android 15 官方模拟器，连接已部署的公网 HTTPS 信令服务；宿主音频关闭，使用独立临时测试 APK 播放幅度为 6000 的 440 Hz 媒体音调。测试时临时测量接收端 WebRTC 解码后 PCM 峰值，未保存媒体音频文件；测量代码已从交付版本移除，测试 APK 已卸载。

| 播放媒体，麦克风静音 | 稳定约 5792–5813 | 系统声音独立传输 |
