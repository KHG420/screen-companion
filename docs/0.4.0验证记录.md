# 0.4.0 视频与聊天验证

日期：2026-09-25。范围：双人房间、Android 10+ 工程与电脑网页；不包含 iOS、多人与 SFU。

## 已执行

- Android：assembleDebug、testDebugUnitTest、lintDebug 均通过，既有 9 个单元测试通过。
- JavaScript：8 个测试通过，覆盖消息边界/格式、历史容量、发送背压、断线禁发，以及摄像头授权尚未返回时挂断的资源释放。
- 真实 Chrome WebRTC 连接：17 项受控媒体检查通过，包含双向摄像头解码、中文/表情文字、摄像头与 3840×2160 屏幕轨道并行、独立关闭与重开、实时画质调整、屏幕声音/麦克风独立控制、ICE 重启和挂断清理。
- Android 35 官方模拟器 ↔ Chrome：双向摄像头可见；浏览器实际解码安卓屏幕 1080×1920 与摄像头 720×1280，轨道独立；安卓前后摄像头切换通过。
- Android ↔ Chrome：中文及表情消息到达安卓，安卓回复到达浏览器；拒绝摄像头权限不影响通话，授权后可重试；无摄像头环境给出可读错误。
- Android 房主 ↔ Android 加入方：建立通话，摄像头画面接收成功，文字消息到达。
- 独立关闭安卓摄像头后屏幕仍在共享；挂断后安卓返回首页，camera service 的 Active Camera Clients 为空，电脑返回首页且两个摄像头元素释放媒体流。
- 安装包和已跟踪文件扫描未包含私有测试服务地址或凭证。服务地址默认留空。
- 界面检查：电脑双摄像头与聊天并排；安卓预览与聊天输入可用。测试截图和原始输出保留在本地忽略目录。

## 测试环境与边界

浏览器使用 Canvas 和合成音频作为受控输入；模拟器启用了 emulated 前后摄像头。验证的是实际 WebRTC 编解码、消息传输、权限流程及资源管理，不代表物理摄像头的成像质量或真机听感。测试使用本地信令和临时 TURN，既观察到直连，也验证了中转路径。局域网 RTT 不能代表公网或移动网络时延。

未验证所有安卓厂商的后台相机策略、Windows/macOS 实体摄像头及 4G/5G 长时间运行。摄像头目标为 720p/30 FPS/2 Mbps；4K 参数继续只作用于屏幕共享。两端应同时升级到 0.4.0，旧版不能区分两路视频。

安装包为 debug 签名测试版，不是应用商店正式签名。
