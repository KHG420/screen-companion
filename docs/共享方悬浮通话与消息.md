# 共享方悬浮通话与消息

日期：2026-09-26。本轮主要处理安卓共享方切换到其他应用后的通话可见性，同时移除网页本地摄像头镜像。

## 交互

- 安卓共享屏幕时，离开应用自动进入系统画中画，优先显示对方摄像头；对方未开摄像头时使用本地预览，两者都没有时显示通话状态。
- 小窗底部随消息更新，显示对方最新消息和未读数量。长消息最多展示三行，回到应用可查看全文、历史并回复。不把小窗摘要当作已读，避免漏掉历史消息。
- “画质与声音”中提供“共享时自动悬浮”和“悬浮窗显示视频”两个独立开关；关闭视频仍保留消息。可手动点击“悬浮通话与消息”进入小窗。
- 主页面在聊天面板关闭时显示最新未读消息条，点击打开聊天。
- 没有可见通话窗口时，已获系统通知权限的设备收到新消息通知；点击返回通话。通知采用私密锁屏可见性，退出通话清理通知。系统通知权限和勿扰设置仍决定通知能否弹出。
- 网页移除本地摄像头的 scaleX(-1)；安卓保留现有 setMirror(false)。

采用系统画中画与主页面完整聊天的分工，没有新增悬浮层特殊权限、生产依赖、服务器接口或媒体连接。画中画的位置、大小与系统控制由 Android 管理；部分设备需要在系统设置允许画中画。

共享整个屏幕时，系统可能把小窗和通知也包含在共享内容内，沿用共享前已有的内容可见性提示。此次没有承诺将小窗从屏幕采集中排除。

电脑网页跨应用悬浮聊天窗口不在本轮安卓实现内；网页本轮只修改镜像。

## 验证

两台 Android 35 ARM64 模拟器使用虚拟摄像头与真实本地信令完成以下流程：

1. 双方进入同一房间、开启摄像头，共享方开始整个屏幕共享并回到桌面；确认 Activity 进入 pinned 模式。
2. 对方发送 `LIVE-MESSAGE-123`，截图确认小窗同时显示视频与消息，返回应用后未读条保留该消息。
3. 关闭“共享时自动悬浮”，回到桌面后确认无 pinned Activity。对方发送 `BACKGROUND-MESSAGE-456`，系统通知记录中出现该正文。返回应用可见两条未读；打开聊天能看到两条完整消息。
4. 另一次通话关闭“悬浮窗显示视频”，对方发来 `MESSAGE-ONLY-789`；即使对方开启摄像头，小窗仍仅显示通话状态与消息。截图人工确认。
5. 结束通话，检查两端 AndroidRuntime 无 FATAL EXCEPTION。

系统画中画不在 launcher 的常规 UIAutomator 文本树中；因此小窗文字采用截图核验，主页面未读、聊天全文和开关采用 UIAutomator 验证。模拟器转换画中画时存在动画延迟，最终截图在状态稳定后取得。

网页 38 项现有测试通过；Android 18 项现有单元测试通过；最终 Debug、Release 构建和 lint 通过（0 错误、8 条既有警告）。测试证明功能可用，不代表低端真机帧率或所有厂商画中画行为。没有新增服务端媒体处理。
